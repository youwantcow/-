# 2차병합 상세 · 제작 지침 v2.3 별책 (kit/docs/2차병합.md)

> 제작 지침 v2.2의 7-2 전문과 부록 B 「2차 검토(`review_kit.py`)」를 **글자 그대로** 옮긴 것이다(v2.3에서 매 턴 읽히는 본체를 줄이려고 — 동작·규칙은 그대로). `2차병합` · `보정 마감` · `녹음 확인`, 그리고 `보정` 끝 · `검토요청`에서 review_kit을 돌릴 때만 읽는다. 5단계 (b)의 03 편집 규칙(`ctx_edit.py`)은 `컨텍스트.md`에 있다. 이 파일 안의 「부록 B」는 이 파일 아래쪽 절을 가리킨다.

### 7-2. `2차병합` 상세
입력은 강의록 · 보정로그(지식 `강의록/` `보정로그/` — 첨부되면 첨부)와 Gemini가 채운 표(검토요청의 배치별 출력, 여러 파일이어도 된다)다. 지식의 파일은 작업 폴더로 내려 쓴다. 기계적인 일은 `review_kit.py`가 하고 Claude는 채택 여부만 판단한다(명령은 부록 B).

1. **대조** — `check`를 돌려 출력 「요청 배치 k개 · n행 = 받음 a + 누락 b (중복 · 모르는 ID · 표 2)」와 배치별 수치를 채팅에 그대로 보고한다. 받은 행이 없는 배치는 '아직 안 받은 배치'로 따로 나온다(모든 배치를 받았으면 `--all`로 전체를 센다). **누락이 있으면 멈추고** 생성된 `재요청_[강의명].md`만 제시한다 — `apply`는 모든 출력을 받은 뒤 한 번만 한다(두 번 나눠 반영하면 ID가 어긋난다). 사용자가 `2차병합 누락 무시`라고 하면 받은 것만 반영한다. `make`에서 `--batch`를 바꿨다면 같은 값을 준다.
2. **판단** — `검토결과_[강의명].md`를 한 행씩 본다. Gemini의 확신 칸은 참고만 한다. 채택 조건은 ① 근거의 음절 대응이 실제로 성립하고(음절거리 참고: 0 = 같음, 0.5 이상 = 발음이 멂) ② 문맥·강의자료와 맞고 ③ 원문 범위를 넘어 말을 보태지 않는 것. 강의자료나 교과서 내용을 교수님 발언으로 끼워 넣는 후보는 그럴듯해도 기각한다. 표 2는 강의록 출현이 1회인 것만 채택할 수 있다.
3. **결정표** — `결정_[강의명].md`. 첫 줄에 검토결과 머리의 「강의록 지문」 줄을 그대로 옮기고, 판단한 모든 행을 `| ID | 조치 | 후보 | 대상 | 이유 |`로 적는다.
   - 조치: `채택`(〔불명확〕에 후보를 넣음) · `대안`(〔?〕인데 Gemini 후보도 그럴듯함 → 둘 다 남김) · `반대`(Gemini가 1차 추정이 틀렸다고 봄) · `동의` · `기각`. 동의·기각은 강의록을 바꾸지 않고 로그에만 남는다.
   - 대상 칸: 표 2(T행) 채택은 현재 표기, 구형 `[불명확]` 채택은 대체할 원문 어절. 그 밖에는 비운다.
   - 1차 추정과 같은 말을 '대안'으로 적지 않는다(스크립트가 거부한다 → 동의로 적는다).
4. **반영** — `apply`를 돌린다(보정로그가 지식에 없으면 — 이미 마무리한 강의록에 추가 검토를 다시 합칠 때 — `--log` 없이 돌리고 5단계의 (a)(b)는 건너뛴다). 반영 형식: 〔불명확: ○○〕 채택 → `후보〔?원문: ○○〕` · 〔?〕 대안 → `〔?원문: ○○ · 대안: 후보〕` · 반대 → `〔?원문: ○○ · 2차 반대〕` · 표 2 채택 → `후보〔?원문: 현재 표기〕`. 스크립트가 실패로 알린 행은 고쳐서 다시 돌리거나 이유와 함께 보고한다. 보정로그에 「N. 2차 검토(Gemini) 반영」 절이 자동으로 붙는다.
5. **마무리** — 순서대로:
   - (a) 보정로그의 「녹음으로 먼저 다시 들을 곳」을 2차 결과로 갱신한다: 채택·대안으로 후보가 생긴 것, 두 AI가 같은 추정인 것, 아직 후보가 없는 것을 나눠 적고, 시험·출제·강조·제외 발언에 걸린 후보는 ID와 함께 추가한다.
   - (b) 보정로그 3절(용어집 추가 후보)을 `ctx_edit.py glossary-log`로 03 4절에 넣고 03을 지식에 교체한다. 충돌(같은 STT 표기에 다른 올바른 표기)은 바꾸지 않고 채팅에 적는다. 일상어와 겹치는 쌍에는 "(○○ 문맥)" 조건을 붙여 넣는다.
   - (c) 보정로그 4절(시험 관련 발언 색인)을 2차에서 바뀐 것까지 반영해 강의록 **머리말 끝**에 「시험 관련 발언 색인」 표로 옮겨 적는다(머리말은 `---` 줄 위다 — `---`만 있는 줄을 머리말 안에 만들지 않는다). 제작 Step 1이 이것을 출발점으로 쓴다.
   - (d) 강의록 머리말의 「상태:」 줄을 `상태: 완성본 (2차병합 YYYY-MM-DD)`로 바꾸고(없으면 만든다), 갱신한 강의록(완성본)을 **제시**하고 지식 `강의록/강의록_[강의명].md`를 교체한다. 지식의 `보정로그/보정로그_[강의명].md`는 **지운다**(채팅 표와 03 용어집과 강의록 머리말로 필요한 것이 다 옮겨졌다). 보정로그 파일 자체는 제시하지 않는다(사용자가 `보정로그 보여줘`라고 하면 그때).
   - (e) 채팅 보고: 「채택 · 대안 · 반대 · 동의 · 기각 · 실패」 수치 → "03 용어집에 n쌍 추가(이미 있음 m · 충돌 k)" → **「녹음으로 먼저 다시 들을 곳」 표**(시각 | ID | 현재 표시 | 걸려 있는 것 | 2차 결과 — 녹음을 들을 때 이 표만 보면 되게). 강의록이 바뀌었으므로 이후 추가 검토가 필요하면 `make`를 다시 돌려 새 검토요청을 만든다.
   - `보정 마감 [강의명]`(2차 검토 생략)일 때는 (a)~(e)를 1차 결과로 한다.
   - 사용자가 녹음을 듣고 확정한 말을 알려 주면(`녹음 확인 …`): 강의록의 해당 표시를 `확정한 말〔녹음 확인 · 원문: ○○〕`로 바꾸고, 그로 인해 용어집에 더할 쌍이 있으면 03에 넣고, 강의록을 교체·제시한다. 그 밖의 글자는 건드리지 않는다.

## 부록 B 중 「2차 검토(`review_kit.py`)」

**2차 검토(`보정` · `검토요청` · `2차병합`)** — `review_kit.py`. ID는 강의록 본문에서 매겨지므로 `make`부터 `apply`까지 강의록을 고치지 않는다(파일 지문으로 확인한다).
```
# 검토요청 파일 만들기 (보정 끝 · `검토요청`)
python3 kit/review_kit.py make work/out/강의록_[강의명].md
# 타임스탬프 블록의 ID 찾기 (보정로그의 「녹음으로 먼저 다시 들을 곳」에 병기)
python3 kit/review_kit.py ids work/out/강의록_[강의명].md 58:37 02:03:29
# Gemini 출력 대조 → 검토결과 · 재요청 파일 (`2차병합` 1단계)
python3 kit/review_kit.py check work/in/강의록_[강의명].md work/in/gemini_*.md --out work/[강의명]/검토결과_[강의명].md    # 재요청 파일도 같은 폴더에 생긴다 → 제시할 때 work/out/ 으로
# 결정표 반영 + 보정로그에 절 추가 (`2차병합` 4단계)
python3 kit/review_kit.py apply work/in/강의록_[강의명].md work/[강의명]/결정_[강의명].md --log work/in/보정로그_[강의명].md --out work/out/강의록_[강의명].md
# 보정로그 3절 → 03 용어집 (`2차병합` 5단계 b)
python3 kit/ctx_edit.py glossary-log work/in/03_[과목].md work/in/보정로그_[강의명].md
```
`make`의 출력(「표시 총 N = 〔?원문〕 a + 〔불명확〕 b = 배치 k개」와 배치 목록), `check`·`apply`의 출력은 채팅에 그대로 옮긴다. Gemini 규칙은 검토요청 파일 머리말에 들어간다(바꾸려면 `make --rules 규칙.txt`).
