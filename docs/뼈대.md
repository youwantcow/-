# 제작 지침 v2.8 · 뼈대 지도 상세 (docs/뼈대.md)

「뼈대 [강의명]」 명령과 Step 4의 4(뼈대)를 받으면 먼저 이 파일을 읽는다. 지침 본문에는 명령표 한 줄과 Step 4의 한 항목만 있고, 쓰는 법 · JSON 문법 · 빌드 명령은 전부 여기 있다. 못 읽었으면 기억으로 만들지 말고 알리고 멈춘다.

## 0. 무엇이고 왜 만드나

학습자료(Part)는 세부를 뜯어보는 자료다. 뼈대 지도는 그 반대 — 강의 전체를 **한 장(A3 가로)** 에 위에서 내려다본 그림이다. 사용자가 손으로 그리던 「도화지 정리」를 대신하는 게 아니라, 사용자가 백지에 먼저 그린 뒤 **대조하는 정답지이자 틀**이다. 그래서 세 번 쓰인다: 예습(뼈대만) → Part 읽는 중(내가 어느 마디의 어느 가지에 있나) → 다 읽은 뒤(빈 뼈대로 백지 인출).

층위는 셋이다.
- **1층 마디(node)** — 강의 전체를 꿰는 10개 이하. 마디마다 「왜 여기서 조절하나 / 왜 이 부류가 따로 있나」 한두 줄.
- **2층 가지(branch)** — 마디당 6개 이하. 제목 + Part · 절 · 쪽.
- **3층 사실(keys / full)** — 가지당 핵심 줄 6개 이하(보드에 보임) + 전문(full, 상자를 누르면 서랍에 열림).

새 사실은 만들지 않는다. 재료는 그 강의의 Part 본문(core)이고, 학습자료에 없는 것은 지도에도 없다.

## 1. 언제 · 입력 · 산출

| 때 | 입력 | 산출 |
|---|---|---|
| Step 4의 4(전 Part 완료 후) | 그 강의의 Part core 전부 · 강의자료 PDF(척추 슬라이드 확인용) | `work/[강의명]/뼈대.json` → `work/out/[과목]_[강의명]_뼈대.html` (+ `.md` · `.canvas`) |
| 뼈대 [강의명] (따로, v2.7까지 만든 강의에도) | 같음 — 다른 채팅이면 core 전부 첨부 | 같음 |

뼈대 HTML은 map_theme.html로 만든 **독립 파일**이다 — `build_part.py --merge`는 `<main>`을 꺼내 잇는 방식이라 뼈대를 받지 못하므로 병합에 넣지 않고 병합본과 나란히 둔다. 강의 틀(표)은 병합본 맨 끝 그대로 — 뼈대는 「어디에 있나」, 틀은 「무엇과 구별되나」로 역할이 다르다.

## 2. 척추 모양 — 강의마다 고른다 (Step 0에 한 줄로 적는다)

도구(한 장 보드 · 층위 · 서랍 · 빈 뼈대 · 가로줄 표)는 늘 같다. 강의마다 다른 것은 **보드 가운데 척추를 무슨 모양으로 두느냐** 하나다.

| 모양 | 이런 강의 | 판단 신호 | 격자 배치 |
|---|---|---|---|
| **흐름**(위→아래) | 한 과정이 순서대로 가고 조절 · 개입이 그 위에 걸림 | 교수님 개요 슬라이드에 화살표가 한 방향 | 척추 `sl`/`sr`(가운데) 세로, 가지는 `l1 l2`(왼) · `r1 r2`(오른). 갈림은 `sl` · `sr` 나란히 |
| **기둥**(나란히) | 같은 급의 것 여러 개를 분류하고 각각의 단계를 비교 | 개요가 「A vs B vs C」 표이거나 「종류: 1, 2, 3」 | 기둥 하나 = 열 하나(`c1 … c5`), 1행에 부류 이름(마디), 아래 행들에 단계(가지)를 세로로. 맨 아래 행에 대비표 |
| **방사**(가운데 하나) | 주제 하나 밑에 순서 없는 항목들 | 개요 슬라이드가 없고 목차가 평평함 | 가운데 열 가운데 행에 마디 하나, 가지를 둘레 칸에. 가지가 8개를 넘으면 2층을 묶어 마디를 2~3개로 쪼갠다 |

**기둥형 배치의 본**(DNA · 유전체 의학과 종양 생화학 1장): 6열 격자에서 기둥 다섯 = `l2` · `l1` · `sl+sr`(span 2, 가장 복잡한 기둥) · `r1` · `r2`. 1행에 기둥 이름(마디, 「왜 이 부류가 따로 있나」), 그 아래 행마다 같은 질문을 둔다 — 「손상 · 신호」 → 「단계」 → 「고장 · 연결」. 같은 행끼리 가로로 읽으면 대비표, 세로로 읽으면 한 경로다. 기둥 위에 흐름 구간(구조 · 복제)이 있으면 마디 하나를 6열로 펼치고(`span: 6`) 가지를 그 아래 한 줄로 깐다(`flow`로 가지 사이에 가로 화살표).

**두 강의를 한 번에 한 강의**(87쪽처럼 길거나, 교수님이 「두 강의」라고 한 것)는 한 장에 넣지 않는다 — 구역을 나눠 JSON 2개(`뼈대_1장.json` · `뼈대_2장.json`), 각각 A3 한 장. 한 장에 욱여넣으면 인쇄 배율이 0.5 아래로 떨어져 읽히지 않는다. 두 장 사이의 연결(복구 → 종양)은 가지의 끝 줄에 「→ 2장 T-3」처럼 적는다.

고르는 기준: **교수님이 강의를 묶으려고 만든 슬라이드가 있으면 그 슬라이드의 모양이 곧 척추**(유전자 발현 조절 2의 p.5–6 8단계 그림처럼). 없으면 목차의 구조, 그것도 평평하면 방사. 한 강의에 둘이 섞이면(복구 5종 = 기둥, 발암 다단계 = 흐름) 보드를 위아래로 나눠 척추를 둘 둔다 — `dividers`로 경계를 긋고 `meta.shape`에 「기둥+흐름」처럼 적되 `shape`는 주된 것 하나로 쓴다(검사는 흐름 · 기둥 · 방사만 받는다).

`meta.shape_reason`에 어느 슬라이드(쪽)가 근거인지 적는다. 근거 없이 고르지 않는다.

## 3. 쓰는 규칙

- **마디 이름**은 슬라이드 표기 그대로(영문이면 영문). 번호 `num`은 슬라이드의 번호(①…)가 있으면 그것, 없으면 부류 이름의 머리글자.
- **「왜」 줄**(`why` · `why2`)은 꼬리표로 시작한다 — `<i class="tg q">교수님</i>` 인용(원문 그대로, 〔?원문: …〕 등 보정 표시 포함, `<q>…</q>`) · `<i class="tg s">자료</i>` 학습자료의 설명(교수님 추가 설명의 요지는 여기 — 인용 부호 없이 「교수님 설명 — …」) · `<i class="tg a">추정</i>` 지도가 더한 연결(한 강의에 두세 개까지, 근거를 같은 줄에) · `<i class="tg x">제외</i>` 출제 제외 언급. 꼬리표 없는 「왜」는 검사에서 △.
- **얇은 마디**(`thin: true`): 이 강의에서 개요만 다룬 마디. 「없다」가 보이는 것도 지도의 정보다 — 빼지 않는다.
- **가지 제목**은 「A. 주제 — 부제」, `ref`는 「P1 · 4–6절 · p.8–11」. 가지는 슬라이드 순서가 아니라 **그 마디에서의 역할 순서**로 (예: 두 축 → 핵수용체 → motif → 켜고 끄기).
- **핵심 줄(keys)**: 명사구 · 방향 사슬(`A → B → C`) · 수치. 110자 안. 시험이 바꿔 낼 칸만 `<b class="k">…</b>`로 감싼다(빈 뼈대에서 가려진다) — 효소명 · 5′/3′ · ↑↓ · 수치 · 「무엇이 쌓이나」. 설명 문장 전체를 감싸지 않는다.
- **전문(full)**: Part 본문의 1순위 결론 · 핵심 요약을 옮긴 `<ul>`. 인용은 `<q>`로 원문 그대로. 여기도 `.k`를 쓴다.
- **기출 · 퀴즈**: 그 개념이 나온 자리에 `<span class="ex">25-1-37</span>` · `<span class="qz">Quiz-2</span>`. 기출 ID는 기출정리의 고정 ID.
- **가로줄 표(tables)**: 마디를 가로질러 묶이는 것 — 같은 분자의 두 결과(IRE 5′/3′), 방향이 갈리는 짝(인산화 ↑/↓), 「어느 단계인가」(동일 교수 기출을 마디에 배치). 2~3개. 표 안의 답 칸도 `.k`.
- **한 문장(one)**: 강의 전체를 한 문장으로. 보드 맨 위에 걸린다.
- 겹침 금지: 같은 사실을 keys와 why에 두 번 쓰지 않는다. 가지의 keys는 보드용 요약, full은 서랍용 전문 — full이 keys의 복사본이면 full을 비운다(서랍은 keys로 대신 채워진다).

## 4. JSON 문법 (work/[강의명]/뼈대.json)

```json
{
 "meta": {"subject":"생화학","lecture":"유전자 발현 조절 2","prof":"박윤규","week":"5주차(10-02)","pages":"p.1–51",
          "date":"2026-11-09","guide":"v2.8","shape":"흐름","shape_reason":"강의자료 p.5–6의 8단계 그림","note":"학습자료 Part 1–4를 재료로, 새 사실 없음"},
 "legend": [{"cls":"c-tx","label":"전사조절 ②"}, {"cls":"c-pt","label":"전사후 조절 ③④⑥"}],
 "one": "<i class=\"tg s\">자료</i>… 강의 한 문장 …",
 "grid": {"cols":["l2","l1","sl","sr","r1","r2"], "widths":[330,330,235,235,330,330]},
 "pills": [{"id":"pDNA","col":"sl","row":1,"span":2,"html":"DNA"},
           {"id":"pDm","col":"r1","row":10,"html":"degraded mRNA","deg":true}],
 "nodes": [{"id":"n2","num":"②","name":"transcriptional control <small>(main)</small>","cls":"c-tx",
            "cat":"전사조절","loc":"핵 · 강의 C 파트 p.5–30","col":"sl","row":2,"span":2,"rowspan":2,
            "why":"<i class=\"tg q\">교수님</i><q>…</q> <span class=\"ref\">p.6</span>","why2":"<i class=\"tg s\">자료</i>…"},
           {"id":"n4","num":"④","name":"transport control","cls":"c-pt","cat":"전사후 조절","loc":"핵 → 세포질","thin":true,"col":"r1","row":5,"why":"<i class=\"tg x\">제외</i>…"}],
 "dividers": [{"row":6,"text":"[Nucleus] 위 · [Cytoplasm] 아래"}],
 "branches": [{"id":"b2a1","p":"n2","cls":"c-tx","col":"l1","row":2,"title":"A-1 DNA 파트(cis) — 조절 DNA 서열","ref":"P1 · 4–6절 · p.8–11",
               "keys":["<b class=\"k\">promoter</b>: basal complex 자리 · …", "…"],
               "full":"<ul><li>…</li></ul>"},
              {"id":"bmi","p":"n6","p2":"n5","cls":"c-tr","col":"r2","row":9,"title":"miRNA — ⑤와 ⑥에 걸친 조절자","ref":"P4 · 7–9절","keys":["…"],"full":"…"}],
 "tables": [{"id":"x1","col":"l2","span":2,"row":10,"rowspan":3,"title":"가로줄 1 · …","ref":"…","html":"<table>…</table>"}],
 "flow": [["pDNA","n2"],["n2","pHN"],["pM","n5"],["pM","n6"]],
 "dash": [["pDNA","n1"],["n3","n4"]],
 "links": [["n6","bmi"]]
}
```

- `grid.cols`는 자유로운 이름(흐름형 `l2 l1 sl sr r1 r2`, 기둥형 `c1 … c5`). `widths`는 px. 폭 합이 A3 가로 한 장 기준 1,900 안팎이면 좋다(합이 커지면 인쇄 글자가 작아진다).
- `row`는 1부터. `one`이 있으면 스크립트가 자동으로 한 줄 내린다(JSON의 row는 그대로 1부터 센다).
- `span`(열) · `rowspan`(행)은 필요할 때만. 두 행에 걸친 마디는 `rowspan: 2`(옛 `two: true`도 받는다).
- `cls`: `c-tx`(빨강) · `c-pt`(파랑) · `c-tr`(초록) · `c-po`(보라) · `c-am`(호박) · `c-tl`(청록) · `c-gy`(회색 — 이 강의 밖 · 개요만). 범주 ↔ 색은 강의마다 `legend`로 정한다.
- `flow`: 척추 화살표(점선 · 화살촉). 아래로 가면 세로/꺾임, 옆으로 가면(기둥형) 가로 곡선. `dash`: 흐름이 아닌 점선 연결(① ↔ DNA 같은 「같은 수준」 표시). `links`: 가지선을 하나 더(걸침). 가지는 `p`(와 `p2`)로 자동 연결되므로 links에 다시 적지 않는다.
- `pills`: 분자 상태 알약(DNA · mRNA · Protein). `deg: true`면 점선(끝점). 기둥형 · 방사형에서는 없어도 된다.

## 5. 절차

1. **재료 읽기** — core 파일(Part마다)의 h2 · 1순위 결론 · [표 해설] · 기출 ID. Part HTML을 통째로 읽지 않는다. 척추 슬라이드(개요 쪽)는 이미지로 직접 본다.
2. **척추 결정** — 2절의 표로 모양을 고르고 `meta.shape` · `shape_reason`. 1층 마디를 먼저 다 쓴다(10개 이하). 마디마다 「왜」. 이 단계에서 채팅에 한 줄: 「척추: 흐름(p.5–6) · 마디 8(얇은 4)」.
3. **가지 · 사실** — 마디마다 가지 ≤ 6, 가지마다 keys ≤ 6 · full. 기출 ID를 건다.
4. **가로줄 표** 2~3개, **한 문장**.
5. **저장 · 빌드**
   ```
   python3 kit/map_kit.py build work/[강의명]/뼈대.json -o work/out/[과목]_[강의명]_뼈대.html
   ```
   출력 「뼈대: 척추 … · 마디 n(얇은 k) · 가지 n · 사실 n줄 · 가로줄 표 n · 빈칸 n · 기출 n · 퀴즈 n · 인용 n · 자료 n · 추정 n · 제외 n」과 △ · ✕ 줄을 채팅에 그대로 옮긴다. ✕가 있으면 파일이 쓰이지 않는다 — JSON을 고쳐 다시 빌드. △는 고치거나 이유를 적는다.
6. **보기 검사** — 가능하면 렌더해 「한 장」 배율에서 겹침 · 빈 칸 · 선이 상자를 가로지르는 곳이 없는지 본다. 기둥형에서 기둥 높이가 크게 다르면 긴 기둥의 가지를 full로 내린다.
7. **Obsidian 내보내기(선택, 사용자가 원할 때)**
   ```
   python3 kit/map_kit.py outline work/[강의명]/뼈대.json -o work/out/[과목]_[강의명]_뼈대.md --links
   python3 kit/map_kit.py canvas  work/[강의명]/뼈대.json -o work/out/[과목]_[강의명]_뼈대.canvas
   ```
   출력 줄(「아웃라인: … [[링크]] n」 · 「캔버스: 카드 n · 선 n」)을 옮긴다.
8. **제시** — 뼈대 HTML(+ 요청 시 .md · .canvas). 병합하지 않는다. 인계 메모의 「진행」에 「뼈대 완료(척추 모양 · 마디 n · 가지 n)」.

## 6. Obsidian에서 쓰는 법 (사용자 안내용)

- **outline .md** — 마디가 `##`, 가지가 `-`, 사실이 `  -`인 들여쓰기 아웃라인. 접기/펴기가 곧 층위다. `--links`를 주면 빈칸 핵심어(`.k`)가 `[[개념]]`이 되어, 같은 개념(HAT/HDAC · proteasome · IRE-BP …)이 여러 강의의 뼈대에서 한 노트로 모인다 — 「이 개념이 어느 강의에 나오나」를 검색 색인으로 쓰는 기존 방식과 바로 맞물린다. 링크는 출발점이라 거슬리는 것은 지운다.
- **.canvas** — 보드가 Obsidian Canvas로 열린다. 카드를 끌어 옮기고 자기 메모 카드를 더 붙일 수 있다(손으로 그리던 도화지의 편집판). 카드 안 글은 마크다운이라 `[[ ]]`를 넣으면 노트로 이어진다. 높이는 어림값이라 처음 열면 한 번 정리한다.
- **빈 뼈대 연습**: Obsidian에서는 outline의 `[[ ]]` 자리만 지운 사본을 만들어 채우거나, 그냥 HTML의 「빈 뼈대」를 쓴다 — HTML 쪽이 더 편하다.

| `유전자발현조절2.json` | 흐름 | 척추 세로 · 갈림(⑤/⑥) · 걸침(miRNA `p2`) · 얇은 마디 · 가로줄 표 |
| `DNA-종양_1장.json` | 기둥 | 기둥 다섯 + 그 위 흐름 두 줄(`span: 6` 마디) · 행 = 손상 · 단계 · 고장 |
| `DNA-종양_2장.json` | 흐름 + 기둥 둘 | 흐름 마디 하나 → 두 기둥(각 `span: 3`) · `links`로 마디 사이 연결 |

새 강의의 JSON은 가장 가까운 예시를 복사해 시작한다. 내용은 전부 바꾸되 격자 · 행 번호의 틀만 빌린다.

## 7. 하지 말 것

- 학습자료에 없는 사실 · 연결을 넣는 것(추정은 꼬리표 달고 두세 개까지). 인용을 다듬거나 보정 표시를 지우는 것.
- 마디 10개 초과(목차가 된다), 가지에 사실을 올려 2층을 3층으로 만드는 것, keys를 문장으로 길게 쓰는 것, 문장 전체를 `.k`로 가리는 것, 답이 둘 이상인 칸을 가리는 것.
- 척추 모양을 근거 없이 고르는 것, 모든 강의를 흐름형으로 그리는 것.
- map_theme.html · map_kit.py를 고치는 것(디자인은 사용자가 템플릿에서), 보드 HTML을 손으로 쓰는 것(JSON → build).
